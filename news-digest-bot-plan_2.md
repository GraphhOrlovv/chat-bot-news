# News Digest Bot — план проекта

Telegram-бот, который раз в день (и по запросу) присылает короткую сводку новостей — около 5 пунктов, из источников с разной позицией, чтобы следить за ситуацией в России и мире без однобокости.

## Требования

- Ежедневная рассылка сводки из ~5 новостей
- Команда/кнопка «Сводка за сегодня» — сводка по запросу, с кэшем на день (не гонять ИИ повторно на каждое нажатие)
- Источники — разные по редакционной позиции
- Этапы использования: сначала только для себя → потом открыть доступ друзьям (самостоятельная подписка через `/start`)
- Полностью бесплатный стек — и хостинг, и ИИ
- Реализация — TypeScript/Node.js; тесты — Python (pytest), независимо от языка реализации
- ИИ-провайдер должен быть легко заменяемым (Gemini ⇄ Claude ⇄ другой)

## Архитектура — 2 слоя

1. **Core-сервис (news-service)** — вся логика: сбор новостей, дедупликация, суммаризация. Отдаёт результат через REST (`GET /digest/today`).
2. **Telegram-адаптер (bot)** — тонкий клиент: подписки, команды/кнопка, расписание. Дёргает core-сервис и форматирует ответ для чата.

Зачем разделять: тесты на Python бьют прямо по REST API, без Telegram-песочницы. ИИ-провайдера можно менять, не трогая бота. В будущем можно добавить другой адаптер (например, веб), не дублируя логику.

## Стек

- Node.js + TypeScript
- **grammY** — Telegram-бот
- **Fastify** — HTTP-сервер для core API
- **rss-parser** — сбор новостей из RSS
- **Google Gemini API** (free tier) — суммаризация; интерфейс позволяет подключить Claude API как альтернативу
- **node-cron** — ежедневный запуск рассылки
- **SQLite (Prisma)** локально → **Turso** (бесплатный облачный SQLite) на этапе с друзьями
- **dotenv** — конфиг/секреты
- **pino** — логи
- **pytest + requests/httpx** (Python) — тесты поверх REST API

## Слой ИИ — интерфейс для смены провайдера

```ts
interface Summarizer {
  summarize(articles: Article[]): Promise<DigestItem[]>
}
```

`GeminiSummarizer` и `ClaudeSummarizer` используют один и тот же промпт, различается только вызов API. Провайдер выбирается через `.env`: `AI_PROVIDER=gemini`.

## Поток данных

- **Ежедневно:** node-cron → `digest.ts` (fetch → dedupe → summarize) → рассылка всем подписчикам из БД
- **По кнопке:** пользователь жмёт «Сводка за сегодня» → `GET /digest/today` → если сводка на сегодня уже посчитана — отдаём из кэша, иначе считаем и кэшируем

## Данные

- `User`: chat_id, subscribed, created_at
- `DigestLog`: date, content (JSON, 5 пунктов), source_articles

## Что нужно завести

- Токен бота через @BotFather
- Ключ Gemini API (Google AI Studio — бесплатно, без карты)
- (позже, на этапе с друзьями) Turso-БД для персистентного хранения подписчиков

## Бесплатный хостинг — по этапам

1. **Только для себя:** локальный запуск (`npm run dev`), без хостинга и БД — свой chat_id зашит прямо в `.env`
2. **С друзьями:** Render (free Web Service) + UptimeRobot (бесплатный пинг раз в 5–10 минут, чтобы сервис не засыпал) + Turso для хранения подписчиков (диск на free Render непостоянный)

## Тесты на Python (отдельно от реализации бота)

Отложено — пишем позже, не в приоритете на текущем этапе (только для себя, без друзей).

pytest + requests бьёт по core API напрямую, без Telegram:

- `GET /digest/today` — структура ответа (5 пунктов, категории, нет дублей)
- `GET /health` — жив ли сервис
- smoke-тест самого бота через Telegram Bot API (`/start`, кнопка отвечают)

## Порядок разработки

1. Core: fetcher + dedupe на 2–3 RSS-фидах (без ИИ, сырые заголовки в консоль)
2. Summarizer (Gemini) — получаем настоящие 5 пунктов
3. Оборачиваем core в Fastify REST API
4. Бот на grammY: `/start`, кнопка «Сводка за сегодня»
5. node-cron — ежедневная рассылка
6. Тесты на Python поверх core API (отложено на потом)
7. Деплой на Render + Turso, когда будешь готов делиться с друзьями
